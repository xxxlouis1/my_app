## 一、改进修正代码：错误从 48 条降到 0 条

### 之前缺什么

原来的流水线有 6 步（剔除 → 切分 → 吸附 → 约束 → 行长 → seconv），但有几类错误
**只是被"掩盖"而不是被修好**：

| 错误 | 原来的处理 | 问题 |
|---|---|---|
| 超长字幕（>10s） | **直接截断**到 10s | 文本还在，但覆盖时长少一半 → 表现为"语音还在说，字幕已消失" |
| 负值 / 超出音频时长 | **完全没处理** | 带非法时间戳交付，Aboboo 可能拒载 |
| 碎片段（几十毫秒） | 保留 | 屏幕上一闪而过，等于没有 |
| 过短段（<800ms） | 只告警 | 不修 |

### 现在新增的四个修复环节

集中放在 `repair_all()`（`model/subtitle_fix.py`），顺序：钳制 → 切超长 → 并碎段 → 延过短。

1. **`clamp_to_media`** —— 负值钳到 0，超出音频时长的钳到结尾；整条越界的剔除
2. **`split_oversized`** —— 超长段**切分而非截断**。优先按词级时间戳切（精确），
   其次按语音区间分派文本，最后按时间等分兜底
3. **`merge_tiny`** —— 时长 <150ms 的碎片并入相邻段（保留文本）
4. **`extend_short`** —— 过短段延长到所属语音区间结束，且不顶到下一条

### 实测效果

| 阶段 | 错误数 | 超长段 | 最长段 |
|---|---|---|---|
| Whisper 原始输出 | **48 条** | 3 条 | 23440ms |
| 自动修正后 | **0 条** | 0 条 | 9844ms |

同时：

- 起点精确命中真实语音起点 **99/100 = 99%**（偏差中位 0ms）
- 文本**零丢失**（443 → 443 词）
- `check_srt` 独立校验：**0 ERROR**
- 结构自检：无重叠、无逆序、无非法时间戳

验证脚本：`scripts/verify_repair_all.py`

## 二、新增错误检测模块（支撑 GUI 错误面板）

新文件 `model/error_detect.py`，产出结构与第一板块的
`view/subtitle_model.py::ErrorInfo` **完全一致**（`subtitle_no / error_type /
message / timestamp_ms`），另附 `auto_fixable`、`hint`、`severity` 三个扩展字段。

### 检测的两类依据

**A. 波形对不齐（时间轴类）** —— 拿字幕起止比对音频波形的真实语音边界

- `时间轴偏移`：起点偏离语音起点
- `终点未覆盖`：终点早于语音结束
- `无语音覆盖`：该时间段检测不到语音
- `时间重叠` / `时间非法` / `时长异常` / `行长超限` / `阅读过快`

**B. ASR 置信度低（识别类）** —— 用 faster-whisper 每条 segment 自带的质量指标

| 指标 | 含义 |
|---|---|
| `avg_logprob` 低 | 置信度不足，常见于噪声/口音/专有名词 |
| `compression_ratio` 高 | 解码陷入重复循环（典型幻觉） |
| `temperature` > 0.2 | 低温解码已失败才升到这里，质量通常差 |
| `no_speech_prob` 高 | 该段很可能是静音被"听"成了话 |

> **重要边界**：这些指标只能**提示可能出错**，不能指出具体错在哪个词。
> 所以识别类错误一律标为"疑似"，且 `auto_fixable=False` —— 自动修正不会去动文本，
> 由人工校对或换更大模型重跑解决。

### 已接入 pipeline

`process()` 的返回值新增 `errors`（GUI 可直接渲染）与 `error_summary`：

```
error_summary : 共 0 条错误 / 101 条字幕
remaining_errors : 0
```

## 三、调优 Whisper 参数：一次实测推翻的调参

### 加了什么

| 参数 | 取值 | 作用 |
|---|---|---|
| `word_timestamps` | True | 词级时间戳，切分与吸附的前提 |
| `hallucination_silence_threshold` | 2.0 | 丢弃静音区内的幻觉词时间戳 |
| `condition_on_previous_text` | False | 抑制"复读机"式幻觉循环 |
| `no_speech_threshold` / `compression_ratio_threshold` / `log_prob_threshold` | 0.6 / 2.4 / -1.0 | 幻觉与低质量的判定门槛 |
| `beam_size` / `best_of` | 5 / 5 | 解码搜索宽度 |
| `vad_parameters` | **None（默认）** | 见下 |

### 踩的坑：凭直觉调 VAD 反而变差

我一开始把 VAD 调成"更灵敏"：

```
min_silence_duration_ms = 300   （默认 2000）
speech_pad_ms           = 200   （默认 400）
```

**结果变差**：

| 配置 | 段数 | 词数 | 时长中位 |
|---|---|---|---|
| 基线（默认 VAD） | **53** | **443** | 4170ms |
| 我的 VAD 调参 | 39 | 440 | 5790ms |

段数从 53 塌到 39，意味着**更多句子被合并成长段**，后续按静音切分只能靠猜，
文本更容易错位。已回退为默认值，并把这条教训写进代码注释。

### 一个方法论注意点

第一次对比之所以"看起来没差别"，是因为 `AsrEngine` 会把传入的 `decode_options`
**合并**到 `DEFAULT_DECODE` 上——旧参数字典里没有 `vad_parameters` 这个键，
于是新加的键仍然生效。必须显式传 `vad_parameters=None` 才能隔离出基线。
