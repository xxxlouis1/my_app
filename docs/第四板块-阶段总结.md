# 第四板块（ASR 识别 + 字幕校正）阶段总结

> **范围**：ASR 识别、字幕时间轴校正、Aboboo 音字对齐
> **时间跨度**：探针实验 → 正式实现 → 参数调优 → 跨模块整合 → 实例素材验证
> **最终状态**：**已通过 Aboboo 实测**，字幕可正常加载、音字对齐正常

---

## 一、我的职责与项目定位

项目是「MP4 字幕矫正工具」：用户导入一个 MP4，输出矫正后的 MP4 + SRT，要求**导入 Aboboo 后音字对齐**。

六人分工中，我负责**第四板块**，也是整个项目最核心的风险点：

| 我的模块 | 职责 |
|---|---|
| ASR 识别 | Whisper 转写、词级时间戳、质量指标采集 |
| 字幕校正 | 时间轴吸附、切分合并、时长约束、行长约束 |
| 错误检测 | 输出 GUI 可渲染的错误清单 |
| 第二板块（兼任） | 批量调度、设备选择、任务状态机 |

**为什么说它是核心风险点**：其他板块（界面、音视频处理、导出）出问题还能绕开，
但字幕时间戳一旦不准，Aboboo 里的复读断点就全部对不上——整个工具失去意义。

## 二、最关键的技术结论（探针实验得出）

在写代码前，我先做了**探针实验**，把"对齐到底由什么决定"这件事钉死。
这些结论决定了后面所有的设计方向。

### 结论 1：Aboboo 对齐**只由 SRT 时间戳决定**，与 MP4 无关

- Aboboo 官方文档明确：**"字幕时间戳用作断点"**
- 实测印证：MP4 用 `-c copy` 重新封装后，2702/2702 帧完全一致，最大偏差 **0.000000 ms**
- 官方还明确：**"原文字幕和译文字幕的时间戳必须相近，最好相同，否则后加载的字幕会覆盖之前加载的字幕"**

**这直接推出三条重要判断：**

| 判断 | 意义 |
|---|---|
| 对齐 = SRT 时间戳的绝对精度 | 全部压力在我们第四板块 |
| 音频标准化对对齐零帮助 | Aboboo 会自行提取音轨、生成断点，标准化只增加负担 |
| MP4 无需重新编码 | 流拷贝即可，速度快、零画质损失 |

### 结论 2：Whisper 的时间戳**系统性偏早**，必须校正

以为波形的真实语音起点为基准实测：

| 模型 | 偏差中位 | 偏早占比 | 标准差 |
|---|---|---|---|
| small | **−92.1 ms** | 85.4% | 133 ms |
| large-v3 | **−266.7 ms** | 88.5% | 156 ms |

**关键推论**：偏差的标准差远大于中位数，说明误差是**随机的**，
不能靠"全局加一个固定偏移量"解决，**必须逐条吸附到真实语音边界**。

### 结论 3：吸附要用"下一个语音起点"，不能用"最近"

两种规则实测对比：

| 规则 | 起点偏差中位 | 可用性 |
|---|---|---|
| 吸附到"最近"的语音起点 | **2403 ms** | 完全不可用 |
| 吸附到"起点之后第一个"语音起点 | ≈0 ms | 采用 |

因为 Whisper 起点偏早，它的起点常常落在**上一句的语音区间内**，
"最近"会把它拉回上一句，产生台词级别的错位。

**例外规则（存有优先）**：若起点确实落在某个语音区间内部，则吸附到**该区间的起点**。
这条规则修掉了 `Project` 那条 267.360s 的实际错位。

### 结论 4：字幕消失得比声音早，要改终点规则

用户实测反馈"字幕消失得比声音早"。根因是旧规则只接受"不晚于字幕末端"的语音终点，
恰好把每个更晚的真实终点都排除掉。

改为**终点延长到起点所属语音区间的结束**后，早结束 >50ms 的条数从 **88 → 0**。

## 三、实现的工作

### 3.1 正式模块（第四板块）

| 文件 | 职责 |
|---|---|
| `model/asr.py` | Whisper 封装、词级时间戳、4 项质量指标采集 |
| `model/waveform.py` | 音频波形分析、语音/静音边界、**自适应静音阈值** |
| `model/subtitle_fix.py` | **核心**：剔错、切分、吸附、约束、行长、全量修复 |
| `model/error_detect.py` | 错误检测，输出 GUI 兼容结构 |
| `model/pipeline.py` | 串联全流程：抽音频 → 转写 → 校正 → 导出 |
| `model/seconv_tools.py` | 调用 Subtitle Edit 做字幕工程规范 |
| `model/gpu_env.py` | CUDA 运行库探测与配置 |

**流水线顺序（不可调换）：**

```
剔除无效段 → 按静音切分 → 波形吸附 → 全量修复 → 约束 → 行长 → seconv 规范化
```

### 3.2 第二板块（批量调度）

`controller/scheduler.py` + `controller/qt_worker.py`：
批量任务队列、设备自动选择（auto/cuda/cpu）、并发控制（GPU 推理串行化）、
任务状态机、失败隔离、取消支持。**30 项测试全通过。**

### 3.3 自动修正：做到"能修的都修掉"

核心思路是**不掩盖错误，而是真正修好**。

| 错误类型 | 原来的处理 | 现在的处理 |
|---|---|---|
| 超长字幕（>10s） | **直接截断** → 文本还在但覆盖少一半 | **切分**（优先按词级时间戳，精确） |
| 负值 / 超出音频时长 | **完全没处理** | 钳制回合法范围 |
| 碎片段（<150ms） | 保留，屏幕一闪而过 | 并入相邻段（保文本） |
| 过短段 | 只告警 | 延长到语音区间结束 |

**效果：`test.mp4` 上错误从 48 条降到 0 条**，同时起点命中 99%、文本零丢失。

### 3.4 错误检测（9 类）

两类依据：

**A. 波形对不齐（时间轴类）** —— 客观参照，与模型无关
时间轴偏移、终点未覆盖、无语音覆盖、时间重叠、时间非法、时长异常、行长超限、阅读过快

**B. ASR 置信度低（识别类）** —— 用 faster-whisper 自带的质量指标

| 指标 | 含义 |
|---|---|
| `avg_logprob` 低 | 置信度不足（噪声/口音/专有名词） |
| `compression_ratio` 高 | 解码陷入重复循环（典型幻觉） |
| `temperature` > 0.2 | 低温解码已失败才升到这里 |
| `no_speech_prob` 高 | 静音被"听"成了话 |

> **重要边界**：这些指标只能**提示可能出错**，不能指出错在哪个词。
> 所以识别类错误一律标"疑似"且**不自动改文本**——避免制造新错。

### 3.5 跨模块整合（接入成员3 的音视频模块）

把成员3 的 `media_processing` 落到项目并打通界面：

- 新增「Aboboo 界面」页签：总波形 + 联动括号 + 单句波形 / 视频 + 字幕列表 + 错误面板
- 波形在**后台线程**生成，不卡界面
- 视频真实帧推送，按帧宽高比绘制不变形
- 播放头联动、点击波形跳转、选中字幕联动单句波形
- 实现「保存 SRT」（原为成员2 的 TODO）

**6 项界面验收全部通过。**

## 五、修正的缺陷清单

### 5.1 我自己代码的缺陷

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | 超长字幕**被截断**而非切分 | 文本还在但覆盖时长少一半 → 表现为"语音还在说，字幕已消失" | 新增 `split_oversized`，按词级时间戳切分 |
| 2 | 负值/超出音频时长**完全未处理** | 带非法时间戳交付，Aboboo 可能拒载 | 新增 `clamp_to_media` |
| 3 | 碎片段未处理 | 几十毫秒的段一闪而过 | 新增 `merge_tiny`（<150ms 并入相邻段） |
| 4 | `min_anchor_speech=0.30` 不适配短句素材 | 598 段砍到 313 段，近一半正常短句当噪声 | 改 `0.15` |
| 5 | **长语音区间被误当成"一句话"** | 19s/57s 区间导致**大量误报**，还可能把字幕拉成几十秒 | 新增 `max_region_sec=6.0` |
| 6 | 吸附会把终点延长到超长区间结束 | 字幕变成几十秒长 | 加区间长度限制 |
| 7 | 诊断脚本硬编码锚点阈值 | 命中率被低估成 76%（实际 91%） | 统一取 `FixConfig.min_anchor_speech` |
| 8 | `.gitignore` 被写成混合编码 | 文件无法读取 | 重写为干净 UTF-8 |
| 9 | 1GB 打包目录未排除 | 差点把 1GB 推上 GitHub | 加 ignore 规则 |

### 5.2 队友代码的缺陷（整合时发现并修）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `AbobooView` **从未给单句波形喂数据** | 单句波形区永远是空的 | 新增 `set_segment_waveform` |
| 2 | `WaveformCanvas` **没有播放头** | 无法实现"播放头与波形同步" | 新增 `set_playhead` + 绘制 |
| 3 | `SRTExporter` 默认 **utf-8-sig（带 BOM）** | 与项目"无 BOM"标准冲突 | 显式改 `encoding="utf-8"` |
| 4 | 成员3 的集成测试用字典下标取对象 | 测试脚本崩溃 | 模块正常，改用属性访问验证 |

### 5.3 踩过的坑与教训

| 教训 | 详情 |
|---|---|
| **"调参"必须实测，不能凭直觉** | 我一度把 VAD 调"更灵敏"（`min_silence_duration_ms` 2000→300），结果段数从 53 塌到 39，切分只能靠猜，文本更易错位。已回退并写进代码注释 |
| **对比实验要确认参数真的隔离了** | `AsrEngine` 会把传入参数**合并**到默认值，旧字典里没有新键 → 新键仍生效，导致第一次对比"看起来没差别"。必须显式传 `vad_parameters=None` |
| **干净素材会掩盖缺陷** | `test.mp4` 上 0 错误，换真实素材立刻暴露 51 条。**必须用真实素材验证** |
| **离屏 UI 测试的陷阱** | `QMessageBox` 是模态的会永久阻塞；嵌套 `app.exec()` 与 `processEvents` 混用会挂死 |
| **不要相信工具的自我报告** | seconv 报告"utf-8 (with BOM)"对每个 UTF-8 文件都这么说，BOM 只能靠字节级检查 |

## 九、几点体会

**1. 先把原理钉死，再写代码。**
探针实验花的力气，比后面任何一次调参都值。正因为确认了"对齐只看 SRT 时间戳"，
我才知道不该在音频标准化、MP4 重编码上浪费时间，全部压力集中到时间戳精度。

**2. 客观指标全绿，不等于好用。**
我一度拿到"起点命中 99%、结构错误 0、文本零丢失"的全绿成绩，
但用户实测反馈"字幕消失得比声音早"——这个指标我根本没测。
后来把它加进验收清单，才真正修好。

**3. 干净素材会骗人。**
`test.mp4` 上错误 0 条，换成真实的卡通素材立刻暴露 51 条。
如果没有那次实例验证，我大概会带着"全部通过"的结论交付一个在真实素材上很差的工具。

**4. 自动化校验器值得单独写。**
`check_srt.py` 不信任任何模块的自我报告，只做字节级和结构级检查。
它后来抓出了 BOM、零间隙等多个工具自身报告不出来的问题。

**5. 诚实说明边界比夸大成果更有用。**
"整段长视频转写不可复现"这个问题我没能定位根因，如实写进文档，
比含糊带过更有利于后续接手的人。
