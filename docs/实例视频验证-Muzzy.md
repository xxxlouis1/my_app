# 实例视频验证：Muzzy Dvd1-2.mp4

用用户提供的实例素材做真实场景验证。这份素材和之前的 `test.mp4` 差别很大，
暴露了三个此前没暴露的问题。

---

## 一、素材规格

| 项 | 值 |
|---|---|
| 文件 | `Muzzy Dvd1-2.mp4` |
| 大小 / 时长 | 161 MB / **858 秒（14.3 分钟）** |
| 视频 | **HEVC (H.265)** 720×580 @25fps |
| 音频 | AAC 44.1kHz 立体声 |
| 内容 | BBC《Muzzy》少儿英语动画，**含大量背景音乐与音效** |
| 内嵌字幕 | 只有 14 个章节标记，**没有真实字幕轨**（不能当标准答案） |

---

## 二、暴露的问题与修复

### 问题 1：锚点阈值在短句素材上过严

`min_anchor_speech = 0.30` 是在 `test.mp4`（跟读素材）上标定的，
那份素材的语音段中位 **1077ms**，0.30 只滤掉噪声。

但 Muzzy 的语音段中位只有 **334ms**：

| 阈值 | 锚点数 | 丢弃 |
|---|---|---|
| >300ms（旧默认） | 313 | 285 段 |
| >150ms（新默认） | **392** | 206 段 |
| >100ms | 445 | 153 段 |

旧阈值把**近一半正常短句**当成噪声丢弃，直接导致"无语音覆盖"误报
从 6 涨到 17。

**修复**：默认值改为 `0.15`（仍能滤掉 27~96ms 的噪声碎片）。

### 问题 2：长区间被误当成"一句话"

这是最重要的发现。含背景音乐的素材里 `silencedetect` 找不到静音，
会把整段音乐+对白识别成**一个超长"语音区间"**：

```
序 12 'Muzzy. Big Muzzy.'  [98.441-107.840]
     所属语音区间 [98.441-118.013]   ← 19.5 秒
序177 'I, you, oh.'        [750.640-758.556]
     所属语音区间 [742.700-799.508]  ← 57 秒!
```

旧逻辑假设"一个语音区间 = 一句话"，于是：
- 判定"终点未覆盖"（区间还有 10 秒没覆盖）—— 其实正常
- 判定"时间轴偏移"（起点离区间起点 9.8 秒）—— 其实正常
- 还可能把字幕终点延长到区间结束 —— 会把字幕拉成几十秒

**修复**：新增 `FixConfig.max_region_sec = 6.0`。超过 6 秒的区间只用来
确认"这段时间里有声音"，不参与对齐精判，也不作为终点延长依据。

### 问题 3：命中率指标本身算错了

诊断脚本里硬编码用 `0.30` 的锚点去衡量用 `0.15` 吸附出来的结果，
导致命中率被低估（76% 而非 91%）。已改为统一取 `FixConfig.min_anchor_speech`。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 残留错误 | **51 条** | **10 条** |
| 终点未覆盖 | 20 | 1 |
| 时间轴偏移 | 9 | **0** |
| 无语音覆盖 | 17 | 2 |
| 起点精确命中 | 81.1% | **90.7%** |
| check_srt | 0 ERROR / 71 WARN | **0 ERROR** / 87 WARN |
| 文本完整性 | 467 → 467 | 462 → 462（零丢失） |
| 结构自检 | 通过 | 通过 |

剩余 10 条中 **7 条是"阅读过快"**（字符/秒超限），属文本密度问题，
自动修正不动文本，需人工精简或拆分。

`test.mp4` 回归无退化：0 错误、命中率不变、端到端全过。

## 四、必须说明的限制：整段转写不可复现

同一模型、同一音频、同一参数，**整段 14 分钟视频跑三次结果不同**：

| 次数 | 段数 | 词数 | 耗时 |
|---|---|---|---|
| 1 | 98 | 467 | 76.8s |
| 2 | 71 | 462 | 74.5s |
| 3 | 89 | 470 | 36.9s |

已排除的可能与已验证的事实：

- 60 秒切片跑 3 次 → **完全一致**
- 300 秒切片（对白+音乐）跑 2 次 → **完全一致**
- 强制 `temperature=[0.0]`（禁用采样回退）→ 300 秒切片仍一致，
  但**未能消除整段波动**

**结论**：波动只在"整段长音频"上出现，短切片稳定。未能完全定位根因
（怀疑与长音频的 VAD 分块 + GPU int8_float16 数值差异有关）。

**影响**：这类素材的 SRT **不是逐字节可复现的**，重跑会有小幅差异；
但对齐质量指标稳定（起点命中 89~91%，check_srt 恒为 0 ERROR）。

**建议**：若需要完全可复现，把长素材按固定长度（如 300 秒）切片后
分别转写再拼接。

## 五、对 Aboboo 对齐的实际意义

实例验证用的是**时间轴**指标，这些直接决定 Aboboo 的断点位置：

- 起点命中真实语音起点 **90.7%**（偏差中位 0ms）
- 终点覆盖：只剩 1 条未覆盖
- 无重叠、无逆序、无零时长
- 输出 UTF-8 无 BOM、LF 换行

## 六、复现命令

```bat
set_env.bat
venv\Scripts\python.exe scripts\process_example.py "Muzzy Dvd1-2.mp4"
```

首次跑会转写（约 75 秒），之后自动复用
`test_output/muzzy/Muzzy Dvd1-2.transcript.json` 缓存，调参只需 1 秒。
加 `--no-cache` 可强制重新转写。
